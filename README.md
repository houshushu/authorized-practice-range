## 一、前言

1. 本课程以实践教学为主，全部实验均在课程组统一搭建并托管的**教学靶场**内完成。靶场内的每一个实验对象（移动端应用、桌面端程序、网络接口、样本与脚本），均为学校为教学目的自行搭建，或已取得环境所有方书面授权；**其中不包含任何商业软件，也不涉及任何商业软件的破解**。
2. 学生开展实验前，应首先确认该课次的授权条目（授权编号载于该课次说明首部），并在授权范围内使用本仓库提供的材料。超出授权范围的使用行为，与本课程无关，课程组不承担责任。
3. 本课程的考核以**过程记录与结论的完整性**为依据，不以是否取得某一具体目标结果作为评分依据。
4. 技术手段应与其使用场景相匹配。学生须确保全部操作仅发生在靶场环境之内，不得以本课程所学对任何未获授权的对象实施。

## 二、授权范围与依据

### 2.1 授权对象（仅限以下三类）

1. **学校教学环境** —— 学校为教学目的自行搭建并托管的模拟应用、模拟服务端、模拟固件与模拟设备，其中实体设备包括：
   - iOS 靶机 `LAB-DEV-01` ~ `LAB-DEV-12`（越狱机、免越狱机各 6 台）
   - macOS 打包机 `LAB-MAC-01`、`LAB-MAC-02`（供桌面端课次打包与验证，须经课程群预约）
2. **已获书面授权的第三方环境** —— 由环境所有方签署授权书后交付课程组使用的对象，授权编号见课次表。**本学期已排课次均为学校为教学目的搭建的教学对象，暂无第三方条目。**
3. **完全合成的样本** —— 学校为教学目的自行构造的假数据、假密钥、假证书与假接口返回，用于替代真实业务数据。

### 2.2 不在授权范围内的对象

任何公网真实服务、任何未取得书面授权的应用及其数据、任何个人设备上的真实账号与隐私数据，均不在本靶场授权范围内。

### 2.3 授权生效方式

授权按课次生效，不整体打包。学生开展某一课次实验，以该课次的授权条目与材料为限。本学期**已排课次**如下：

### 3.3 材料获取与校验

1. 体积较小的材料随本仓库 `labs/<课次>/assets/` 下发；
2. 体积较大的材料（第一课源码包、第二课课件包）通过本仓库 Release 下发，下载命令载于该课次说明；
3. 每份材料均附 `sha256` 校验值，**开工前须完成校验，校验不一致的材料不得使用**；
4. `setup/` 下的启动与还原脚本随**课程环境包**统一下发，不在本仓库内。校外访问须先接入课程 VPN，从课程组内网盘获取。`logs/`、`notes/`、`tools/` 由学生在本机实验目录自行建立。桌面端课次（如第一课）以本机 macOS 为实验环境，不需要 `setup/` 脚本。

### 3.4 通用流程

```bash
# 1. 阅读该课次实验说明（授权条目、实验目标、验收标准均在其内）
less labs/lab02-去广告与SVIP解锁/README.md

# 2. 取得课程环境包后，执行包内脚本启动实验环境（桌面端课次跳过此步）
bash <课程环境包目录>/setup/start.sh

# 3. 实验产物存放：日志 → logs/   笔记 → notes/   脚本 → tools/
```

### 3.5 环境可重建原则

实验环境均为可重建、可丢弃环境。环境损坏时，重新执行 `setup/start.sh` 即可重建，不要求修复。iOS 靶机异常时执行 `setup/reset.sh` 还原出厂快照；macOS 打包机使用完毕后应通过课程群归还。

## 四、实验环境与操作规范

1. **环境使用**：实验应在指定靶机或本机实验目录内进行；不得在实验环境中登录任何真实账号。实验产物应按 3.4 规定存放，以便提交与验收。
2. **安装与还原**：修改后的安装包应通过 TrollStore 或经重签名的侧载方式装回靶机，所采用的方式须记入过程记录。
3. **材料使用**：本仓库提供的样本、密钥、证书与抓包数据，仅限本课程实验使用，不得用于其他任何对象。
4. **材料流转**：材料不得转发至课程范围之外（包括课程群之外、网盘、公开平台）。

## 六、作业提交与考核

### 6.1 评分构成

| 部分 | 占比 | 说明 |
|---|---|---|
| 过程记录 | 40% | 命令、日志、报错与排查过程 |
| 结论与证据 | 40% | 每条结论须可指向具体证据（日志行 / 内存地址 / 抓包编号） |
| 复现性 | 20% | 助教按所提交步骤可在干净环境中复现同一结果 |

### 6.2 提交安排

- **提交节奏**：已排课次各提交一次，提交节点以各课次说明为准，截止时间以课程群公告为准。
- **专项验收优先**：各课次均设有专项验收标准 —— lab01「打包产出的 dmg 无缺陷方可得分」、lab02「存在残留或功能异常者不得分」、lab04「出现功能异常者不得分」。专项验收未通过者，该课次不计分。
- **提交方式**：将 `notes/` 与 `logs/` 打包，以 `学号-姓名-labXX` 命名，提交至课程组指定位置。不得以未修改的样本原件作为交付物；改动后的材料应按该课次说明一并提交，供教师验收。
- **组队**：lab01 允许 2 人一组，须在选题表登记分工；**lab02、lab04 独立完成**。

## 七、常见问题

**Q1：实验环境无法启动，应如何处理？**
A：应先查阅该课次说明的「排错」章节；仍无法解决时，于固定答疑时间携带 `logs/` 内的原始报错提交。仅描述"无法启动"而不附报错的咨询，无法定位问题。

**Q2：课件包与源码包在何处获取？**
A：体积较小的课件包位于该课次 `labs/<课次>/assets/` 下；体积较大的材料（如第一课源码包、第二课课件包）位于本仓库 **Release** 中，下载命令载于该课次说明。每份材料均附 `sha256`，使用前须完成校验，校验不一致者不得继续实验。

**Q3：改动到什么程度视为达标？**
A：以该课次说明中的验收标准为准。例如第二课要求广告**被移除**而非被隐藏，页面不得留有空白或占位框；第四课要求补丁最小且功能完好。

**Q4：课程中所学手法能否用于其他对象？**
A：技术原理相同，但授权完全不同。靶场对象由学校为教学目的搭建并经书面授权；其他对象未取得相应授权，不得实施。

**Q5：能否将样本带离实验室自行研究？**
A：可以，但不得转发至课程范围之外。安装样本的设备应按靶场环境管理，不得登录真实账号，亦不得再次分发。

**Q6：能否将本仓库用于作品集或简历展示？**
A：可以展示本人撰写的分析与结论；涉及各课次源码、改动与补丁的内容，须先经课程组确认后方可公开。

**Q7：实验机能否用于课程以外的用途？**
A：不得。`LAB-DEV-01` ~ `LAB-DEV-12` 与 `LAB-MAC-01` ~ `LAB-MAC-02` 均为教学资产，已登记固定资产，仅用于课程实验；iOS 靶机由 `setup/reset.sh` 定期抹除。
