## 一、本次目标

1. 把课件（靶场样本 App）里用到的**全部播放源**提取出来 —— 是"全部"，不是"能抓到的那一个"。
2. 把提取到的源**全部移植进本课源码包**（`移动应用安全与逆向分析_第一课_源码包_授权靶场.zip`，Electron 桌面端源码）。**所有源都要移植成功**，少一个都不算完成。
3. 移植过去的源要作为**主播放源**：默认播放必须走它，不是备选、不是兜底、不是"没网才切"。
4. 用源码包**打包出 dmg**，装上去能直接跑。

> ### ⚠️ 验收标准：**打包出来的 dmg 无 bug 才得分**
>
> 逐条对照，缺一条这次作业就是 0 分：
>
> - [ ] dmg 能正常安装、能正常打开，**不崩、不白屏**
> - [ ] **所有**移植过来的源都能播出画面（逐个点过，不是抽测）
> - [ ] **主播放源生效**：默认走的就是移植那套，能在代码/日志里指出证据
> - [ ] 播放过程**不卡死、不报错、没有明显 bug**（控制台无报错堆栈）
> - [ ] 换一台机器（或一个干净用户）装上同一个 dmg，**结果一致**
> - [ ] 提交物里**含已修改好的课件**：老师解开就能直接看出源移植在哪（见第二节第 2 项）
>
> 只交"能跑一半"的 dmg = 没得分。跑不通就继续调，调不动来周三答疑。

## 二、交付物（四样，缺一样按未完成算）

1. **dmg 安装包** —— 按 `学号-姓名-lab01-dmg` 命名
2. **已修改好的课件（源码包）** —— 把你改完的那份源码打包交上来，按 `学号-姓名-lab01-源码.zip` 命名。

   **这是老师验收的主要依据**：提交的包要能直接解压、直接看出改动（移植的源在哪、主播放源怎么切的），所以：

   - 交**改完之后**的完整源码，不要交原始包（原始包老师手上有）
   - 目录结构保持原样；**`node_modules` 不要打进去**（老师 `npm install` 自装），整个包控制在 5 MB 以内
   - 改动过的文件在「改动说明」里逐个点名（文件路径 + 改动点），方便老师对照
   - 打包命令示例：

     ```bash
     zip -r 学号-姓名-lab01-源码.zip \
       src main.js preload.js package.json package-lock.json assets tools \
       -x '*/node_modules/*' '*.DS_Store'
     ```
3. **改动说明** —— 改了哪些文件、每个文件改了什么、为什么这么改
4. **过程记录** —— 命令、日志、报错、弯路（越真实越好，不用修饰）

> 提交前自查：把 dmg 装一遍、把源码包解压一遍，照着上面的 checklist 走一次 —— **自己先当一次老师**，别让助教替你发现"这包打不开"。

## 五、排错

| 现象 | 先查什么 |
|---|---|
| `npm install` 卡住 / 失败 | 是否连着课程 VPN（靶场网段已放通公共 npm 源）；换课程镜像源再试 |
| 校验失败 | 重新拉一次课件包/源码包，别用被改动过的副本 |
| dmg 打不出来 | `npm install` 是否完整；electron-builder 的 mac 目标与机器架构是否匹配 |
| 装上就崩 | 看控制台报错栈，别猜；把栈贴进答疑 |
| 有的源播不了 | 是源本身的问题还是你没移植全 —— 两个都要排 |

还不行就来周三答疑（B302，14:00–16:00），附上 `logs/` 里的原始报错。
