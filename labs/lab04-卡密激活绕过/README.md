## 一、实验目标

1. **分析**：梳理样本应用的**授权（卡密）校验链路** —— 明确校验发生位置、校验对象，以及校验结果如何决定功能的启用与关闭；
2. **绕过**：绕过授权验证，实现**无卡密激活** —— 在未输入任何卡密的情况下，程序应进入"已激活"的正常状态；
3. **最小补丁**：能够以一处改动解决的，不得改动三处；能够通过修改单个判断结果解决的，不得删除整段逻辑。**改动越小，评分越高**；
4. **功能正常**：除"无卡密亦可进入"外，其余行为须与正版激活状态**一致**，原有功能、界面与数据均不得损坏。

---

## 二、验收标准（专项）

本课次设有专项验收标准：**出现功能异常者，本课次不计分。**

逐项核对，任一项不符合即不予通过：

- [ ] **无卡密可用**：未输入任何卡密即可进入已激活状态，且**冷启动或重启应用后仍然有效**，不得仅在当前进程内临时生效；
- [ ] **原有功能正常**：样本应用的主要功能逐项验证，均可正常使用，无崩溃、无白屏、无卡死；
- [ ] **未引入新报错**：控制台与系统日志中不存在本次改动引入的异常堆栈；
- [ ] **补丁最小**：须在「改动说明」中精确指明改动位置（字节 / 指令 / 函数 / 字符串），并说明该改动已属最小的理由；
- [ ] **可复现**：助教按所提交的补丁与复现步骤，可由**原始包**复现出**所提交的修改包**；
- [ ] **换机一致性**：在另一台靶机（或重装后）安装修改包，结果一致；
- [ ] 交付物中包含已修改完成的课件（修改包 + 补丁文件），教师可直接查看效果。

不予通过的情形：能够进入但功能出现异常。补丁规模略大而功能完好，优于功能残缺的修改包。

## 六、排错

| 现象 | 排查方向 |
|---|---|
| 环境无法启动 | 是否处于 B302 网段内；校外是否已接入课程 VPN |
| 校验失败 | 重新获取课件包，不得使用已被改动的副本 |
| 工具报架构不匹配 | 确认实验机为 arm64 或 x86_64，对应脚本不得混用 |
| 修改包无法安装 | 重签名与描述文件是否完整；越狱靶机建议优先使用 TrollStore |
| 能够进入但功能异常 | 是否删除了整段校验逻辑；应优先仅修改判断结果，不改动流程 |
| 冷启动后恢复未激活 | 仅篡改了内存中的取值，未改动持久化判断点；应查明校验结果的存储位置 |

上述排查仍无法解决时，请于固定答疑时间（周三 14:00–16:00，B302）携带 `logs/` 内的原始报错提交。
