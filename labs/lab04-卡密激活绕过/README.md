## 一、本次目标

1. **先看懂**：把样本的**授权（卡密）校验链路**摸清楚 —— 校验在哪儿发生、校验的是什么、校验结果怎么决定功能的开与关。
2. **再绕过**：**绕过授权验证，实现无卡密激活** —— 不输入任何卡密，程序也要进入"已激活"的正常状态。
3. **最小补丁**：能用一处改动解决的，不许改三处；能改一个判断结果解决的，不许把整段逻辑删掉。**改动越小越分。**
4. **功能正常**：除了"不用卡密也能进"，其余行为必须与正版激活后**一致** —— 原有功能、界面、数据都不能坏。

> ### ⚠️ 验收标准：**功能出现异常不得分**
>
> 逐条对照，缺一条这次作业就是 0 分：
>
> - [ ] **无卡密可用**：不输入任何卡密，也能进入已激活状态 —— 且**冷启动 / 重启 App 后仍然有效**，不是只在当前进程里临时骗过去
> - [ ] **原有功能全部正常**：样本里的主要功能逐个点过，都能正常用，不闪退、不白屏、不卡死
> - [ ] **没有引入新报错**：控制台 / 系统日志里没有你这次改动带来的异常堆栈
> - [ ] **补丁最小**：能在「改动说明」里精确指出改了哪一处（字节 / 指令 / 函数 / 字符串），并说明**为什么这已经是最小改动**
> - [ ] **可复现**：助教按你的补丁 + 复现步骤，能把**原始包**改成**你交的那一份**
> - [ ] **换机一致**：换一台靶机（或重装一次）装上你改过的包，结果一致
> - [ ] 提交物里**含已修改好的课件**：改完的包 + 补丁文件，老师装上就能直接看效果
>
> 只做到"能进去但功能坏了" = **不得分**。宁可补丁大一点但功能完好，也不要交一个功能残缺的包。

## 五、排错

| 现象 | 先查什么 |
|---|---|
| 起不来 | 是否在 B302 网段内 / 校外有没有连课程 VPN |
| 校验失败 | 重新拉一次课件包，别用被改动过的副本 |
| 工具报架构不对 | 确认实验机是 arm64 还是 x86_64，对应脚本别混用 |
| 改完装不上 | 重签名/描述文件是否完整；越狱机上优先走 TrollStore |
| 能进去但功能坏了 | 你是不是把整段校验逻辑删了 —— **优先只改判断结果**，别动流程 |
| 冷启动又变回未激活 | 说明你只骗过了内存里的值，没改到持久化的判断点，回去看校验结果存在哪 |

还不行就来周三答疑（B302，14:00–16:00），附上 `logs/` 里的原始报错。
